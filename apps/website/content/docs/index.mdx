Vaubaan Gateway is a server you run for yourself, then for your team, so that your agents can use your services through MCP without being handed your credentials; these pages are for the people who install it, use it, review it or extend it, and for the agents working through it.

**Pre-release.** Versions `2.0.0-alpha.*` are tagged and published as images; expect breaking changes until `v2.0.0`. Every command on these pages is one that works on the repository today. What was never tried or is not built is listed under [known limitations](/docs/known-limitations).

## Pick your path

### You code alone with an agent

A developer with a coding agent on GitHub and Supabase.

1. [Quick look](/docs/quick-look): the whole interface on a laptop in a few minutes, nothing to register.
2. [Install](/docs/install) an instance for yourself, or [let your coding agent install it](/docs/install/with-your-coding-agent); sign in with an account the instance keeps, no identity provider needed.
3. [Connect](/docs/services) your accounts: [GitHub](/plugins/github#connect), [Supabase](/plugins/supabase#connect). Label the Supabase projects `staging` and `prod` ([environment labels](/docs/accounts#environment-labels)).
4. [Create a mission](/docs/missions#create-a-mission) and give its key to your agent: [MCP clients](/docs/missions/mcp-clients), [git remote](/docs/missions/git-remote).
5. Read [how a permission is decided](/docs/concepts/permissions) before you choose a trust level.

### You work alone with an assistant

A consultant with an assistant on Gmail, Notion and Google Calendar.

1. [Quick look](/docs/quick-look), then [install](/docs/install) an instance for yourself.
2. [Connect](/docs/services) [Gmail](/plugins/gmail#connect), [Notion](/plugins/notion#connect) and [Google Calendar](/plugins/google-calendar#connect).
3. [Create a mission](/docs/missions#create-a-mission) where sending asks you first, and add it to your assistant: [MCP clients](/docs/missions/mcp-clients).
4. Be told when something waits for you: [notifications](/docs/missions/notifications).
5. [How a permission is decided](/docs/concepts/permissions) shows the consultant's mission at each trust level.

### You bring your team

The administrator of an instance for several people.

- [Configuration](/docs/configuration): sign-in through your identity provider, GitHub, Google or Microsoft, and [every configuration key](/docs/configuration/keys).
- [Administration](/docs/administration): people, teams, sign-in, plugins, encryption.
- [Give access](/docs/accounts#give-access) to an account, and add [teammates and machine keys](/docs/missions#teammates-and-keys) to a mission.
- [Operations](/docs/operations): backup and restore, master key rotation, upgrade, telemetry.

### You review its security

- [Trust center](/trust): what protects the credentials an instance holds, what is not covered, what leaves an instance.
- [How a call flows](/docs/concepts/how-a-call-flows): the checks every call goes through, and the three credentials that never cross.
- [Known limitations](/docs/known-limitations) and [how Vaubaan compares](/docs/compare) with handing an agent a token, a secrets manager and other MCP gateways.

### You write a plugin

- [Write a plugin](/docs/plugins-guide): the author's guide, from an empty folder to a plugin running on your gateway or published in the catalog.
- [Plugins](/plugins): every published plugin, its permissions, macro-actions and connect guide, the shape yours will have.
- [How a permission is decided](/docs/concepts/permissions): the five facts and four rows your catalog sorts each permission into.

- [Refusals](/docs/reference/refusals): every code, and what to do about it.
