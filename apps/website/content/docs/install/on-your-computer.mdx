One command starts Vaubaan on your computer, for you alone: no server, no domain name, no certificate, no sign-in provider and no key to generate. It is the same image as a team's instance, in **local mode**.

## Requirements

- Docker (Docker Desktop on macOS or Windows, Docker Engine on Linux), on an Intel or Apple silicon machine.
- Port 3000 free on your computer.

## Start it

```bash
docker run -d --name vaubaan --restart unless-stopped \
  -p 127.0.0.1:3000:3000 \
  -v vaubaan:/data \
  -e VAUBAAN_LOCAL=true \
  ghcr.io/vaubaan/gateway:2.0.0-alpha.31
docker logs vaubaan
```

The output ends with the setup link:

```
Vaubaan runs on this computer. Open this link to set it up:

  http://localhost:3000/admin/bootstrap#token=...
```

Open it in your browser, on this computer. The link changes at each start and stops working once the setup is finished; until then, `docker logs vaubaan` prints the current one.

- **`-p 127.0.0.1:3000:3000`** keeps the instance on this computer. Written `-p 3000:3000`, every machine on your network reaches it; the instance cannot tell from inside its container, and the footer of every page says it is meant for this computer only.
- **`-v vaubaan:/data`** holds everything: the database and the encryption key. Without it, everything is lost with the container.

## Set it up

The link opens the setup, a list of steps with the next one marked:

1. **Your encryption key.** Download the key that seals every credential you connect, and keep it off this computer (a password manager). In local mode the key sits in the same volume as the database: this copy is the only one apart, and a backup opens with it only.
2. **Sign-in.** Choose **Set up sign-in**, then **Add sign-in accounts**: accounts the instance keeps itself, with no identity provider to register.
3. **The first administrator's account.** Choose **Create the account** with your email; open the link it gives, choose a password, then enrol a second factor with an authenticator app and keep the recovery codes.
4. **Finish the setup.** The setup link stops working; from then on you sign in at `http://localhost:3000/login`.

Then [connect an account](/docs/services) and [create a mission](/docs/missions).

## Your agent

Your coding agent runs on the same computer and reaches the instance at `http://localhost:3000`: the MCP door is `http://localhost:3000/mcp`, the git remote `http://localhost:3000/git/...`. A mission's page gives the exact lines to add to your agent, with its key.

## Every day

```bash
docker stop vaubaan       # stops the instance; your missions and accounts stay in the volume
docker start vaubaan      # starts it again
```

**Upgrade** to a newer release: stop and remove the container, then run the command above with the new version. The volume keeps everything; the instance migrates its database at the start. Releases and their notes: [the changelog](https://github.com/vaubaan/gateway/blob/main/CHANGELOG.md).

```bash
docker rm -f vaubaan
docker run -d --name vaubaan --restart unless-stopped \
  -p 127.0.0.1:3000:3000 -v vaubaan:/data -e VAUBAAN_LOCAL=true \
  ghcr.io/vaubaan/gateway:<new version>
```

## Browsers

Chrome, Firefox, Edge and Safari keep the session on `http://localhost`. Notifications on your phone need an instance reachable over https: a team server, not this one.

## What local mode sets

`VAUBAAN_LOCAL=true` sets the keys a server's operator decides, each only when you did not set it yourself:

| Key                             | Local mode's value                                    |
| ------------------------------- | ----------------------------------------------------- |
| `public_url`                    | `http://localhost:3000`                               |
| `store.path`                    | `/data/gateway.db`                                    |
| `encryption.master_key`         | the file `/data/master.key`, generated at first start |
| `accept_shared_address_windows` | on: there is no proxy in front                        |

An `http` public URL is accepted in local mode only, and on `localhost`, `127.0.0.1` or `[::1]` only. To use another port, publish it and say so: `-p 127.0.0.1:8080:3000 -e VAUBAAN_PUBLIC_URL=http://localhost:8080`. Every key: [configuration keys](/docs/configuration/keys).

## Bring your team later

Local mode is for one person. For a team, run an instance on a server with your sign-in: [install an instance](/docs/install). A desktop app for macOS and Windows, which needs no Docker, is planned.
