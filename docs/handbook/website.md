# The public site — handbook

How `apps/website` builds vaubaan.com from the repository at build time, and reads plugin health when a page is served. Spec: [website](../spec/website.md) §2; ADR [website-nextjs-on-vercel](../decisions/website-nextjs-on-vercel.md); the collector sharing the app: [telemetry](telemetry.md).

## Start here

- [`scripts/generate.ts`](../../apps/website/scripts/generate.ts) — the build-time generator; `npm run build`, `dev` and `type-check` all run it first. It reads no network.
- [`src/content/build-site.ts`](../../apps/website/src/content/build-site.ts) — `buildSite()`, every page and public file from what `src/content/` reads in the repository.
- [`src/site/live.ts`](../../apps/website/src/site/live.ts) — what is rendered at request time: the pages under `/plugins`, every Markdown twin (`app/twins`), `plugins.json` and `llms-full.txt`, with the collector read and cached an hour.
- [`src/content/plugin-page.ts`](../../apps/website/src/content/plugin-page.ts) — the page data of `/plugins/<id>`, section by section (spec §2.3, 1–8): `openingOf`, `mapOf` (rows, boxes, `readingOf`), `spreadsOf` (with `columnOf`, `limitsNote`), `callWords`/`carefulGateOf` for the examples, `missionOf`, the connect guide (`connectKindBadge`/`connectKindCode` — the three kinds, numbered —, `brokerAdminSentences`, `connectSentences`, `PATH_SEPARATOR`, `connectGuidePath`, `screenshotCredits`), `retiredOf`. [`components/plugin/PluginPage.tsx`](../../apps/website/src/components/plugin/PluginPage.tsx) renders it as HTML, `pluginPageMarkdown` (`plugin-pages.ts`) as the Markdown twin, both in the same order; [`components/plugin/Codes.tsx`](../../apps/website/src/components/plugin/Codes.tsx) holds the display codes (gate mark, risk word, six fact cells, tag, mono, permission box), styled in `globals.css` under "Display codes".
- [`src/proxy.ts`](../../apps/website/src/proxy.ts) — the collector host gate and the rewrite of `.md` addresses and `Accept: text/markdown` to the twins route.
- [`content/docs/`](../../apps/website/content/docs/) — the hand-written docs; `meta.json` orders the sidebar.

## Invariants

- **The site reads the repository, not a copy.** Plugins are loaded through their `exports["."]` and validated by `definePlugin` and the catalog loader as at gateway boot; the configuration key table, [known-limitations](known-limitations.md), the [threat model](threat-model.md) (`trust.ts`) and the thresholds of `deploy/collector/schema.sql` are parsed from their files. Reshaping one of those docs can break the site: grep `apps/website/src/content/` first.
- **Nothing of the gateway is restated by hand**: severity, tier, gates and budgets come from `@vaubaan/policy-engine` (`severityOf`/`severityLevel`, `tierOf`, `tierFactsOf` — the facts that move the gate —, `TRUST_LEVEL_GATES`, `budgetAtTrustLevel`, `expandAtTrustLevel`, `evaluateCall`, `macroActionsOf` for "Anything else"), and so do the words a person reads of the risk model (`WHY_LABELS`, `WHY_ORDER`, `WHY_VALUES`/`whyValue` — the six facts and the undo word —, `UNDO_ROW_WORDS` — the rows of the map —, `gateWordOf`/`GATE_WORDS`, `ALLOW_WORDS`, `TRUST_LEVEL_LABELS`, `TRUST_LEVEL_HINTS`), which the gateway's `lib/vocabulary.ts` re-exports; the client source comes from `isBrokeredSpec` of the plugin SDK — packages, allowed by the ADR; `apps/gateway` stays forbidden. **`sources-agree.test.ts`** holds it: the gateway's vocabulary exports the very values of the policy engine, every fact the site shows is `factsOf()`'s, and `plugins.ts`, `plugin-examples.ts`, `plugin-page.ts`, `plugin-pages.ts`, `outputs.ts` and `components/plugin/` contain none of those words as a literal (`UNDO_ROW_WORDS` included); beside it, the key page against `KEYS` and the thresholds against the collector README. A word missing from the policy engine is moved there (and re-exported by the gateway when its interface prints it), never written in the site.
- **`plugins.ts` is the data contract of a plugin page** (spec §2.3, sections 1–8): every shape is plain, serialisable data and `plugins.json` writes it out. A macro-action's entries are in catalog order with retired permissions left out (as the gateway's form); `anythingElse` and `retired` are apart from `macroActions`; `counts.permissions` leaves out the fallback and the retired (GitHub: 17). A quota is per period, written per day on the page (a mission's default period); the per-minute ceiling is a note.
- **Examples are classified at build** (`plugin-examples.ts`): each sample of `plugin.examples` goes through the plugin's own `classify`, its slices through the policy engine's matcher, and two decisions: `atCareful` — "what a Careful mission does", the gate Careful gives each permission the call touches (`evaluateCall` against an empty mission names them env-qualified, `TRUST_LEVEL_GATES.careful` on the tier in that environment) — and `inWorkedMission`, what the page's worked mission (the first two macro-actions at Careful, `expandAtTrustLevel` + `evaluateCall`, over the sample's resources) does with it. A tool's `touches` is the union of its examples' permissions. A sample marked `expectDenied` is a test of the refusal: checked, not shown. The site never writes a slice by hand.
- **A plugin page is HTML built from its data, not rendered Markdown** (the other generated pages are): `PluginPageView` and `pluginPageMarkdown` read the same `plugin-page.ts` builders, so a section added to one is added to the other. The map's rows are `MAP_ROWS` (4 → 1, what the trust levels read) named by `UNDO_ROW_WORDS` of the policy engine; a box is a permission in one row, an environment-scoped permission one box per row its environments land in (`tierOf` on each environment's vector, acceptable environments only); the fallback is drawn dashed in "Anything else" and never counted. Each row's sentence and the reading sentence are computed from `TRUST_LEVEL_GATES` and `GATE_WORDS`. **The page never prints "tier"**: `plugin-page.test.tsx` renders every plugin's HTML and twin and refuses the word.
- **Display codes follow the gateway's colour rule**: a status is coloured only when it differs from normal — risk word low plain, medium warn, high and critical bad; gate dot green for runs freely, warn for ask me first, hollow for not included; the six cells plain but the one that moves the gate (`movesGate`); a box tinted by its risk word. An environment tag stays neutral: the gateway's per-environment tone lives in `apps/gateway`, which the site may not import.
- **Every page has a Markdown twin** (`/index.md`, `/docs/….md`), listed in `llms.txt`; the proxy serves the twin when `Accept` ranks `text/markdown` above `text/html`.
- **Health is never invented, and never gated**: the site reads two aggregates in parallel, `/v1/plugin_stats?tool=is.null` (calls, successes, rejected credentials, rate, `validated`) and `/v1/plugin_instances` (distinct gateways per version, minor and plugin). Each that fails, or is skipped (`VAUBAAN_SITE_OFFLINE=1`), turns its own figures into "not read" (`null` in `plugins.json`, with `health_read` saying which). Every version with data shows its figures; `validated` is a word when true, never a threshold on the display. `healthOf()` is the one place that decides; it is pure and takes a snapshot.
- **A minor's gateways come from the collector, never from a sum**: `plugin_instances` groups by minor in SQL so a gateway that moved 4.0.1 → 4.0.2 counts once. Calls and the rate of a minor are sums of its versions' rows (rate = successes / (reports − rejected credentials)).
- **The footnote** (`healthFootnote()`) is on `/plugins`, `/plugins/<id>` and `/plugins/health`, and in `plugins.json`: calls over the window from instances sharing plugin health; gateways among those also sharing usage statistics, a lower bound; rejected credentials left out of the rate.
- **Health is read when a page is served, once an hour for the whole site**: every route that imports `src/site/live.ts` exports `revalidate = 3600` (`live.test.ts` keeps the literal equal to `HEALTH_REVALIDATE_SECONDS`), and the collector fetch sits in the Next.js data cache for the same hour. What repeats a plugin page (its twin, `plugins.json`, `llms-full.txt`) is rendered by the same functions, so it shows the same figures.

- **The versions feed's data are committed files, not pages** ([ADR](../decisions/plugins-bundled-or-pinned-by-the-operator.md)): `src/content/releases.json` (`{ gateway, prerelease, date, plugins: { <id>: <version> } }`) is written by `npm run release:prepare` — at a gateway release from the root and every `plugins/*/package.json` but `_template`, at a plugin hotfix (`-- --plugin <id>`) that plugin's entry alone; never edited by hand. `src/content/advisories.json` is a JSON list, hand-written in the fix's pull request, one object per advisory, the shape of `VersionsFeedAdvisory` (`@vaubaan/shared/versions-feed`, which the gateway checks): `id` (`VBN-<year>-<nnn>`), `subject` (`gateway` or `plugin:<id>`), `affected` (a semver range), `fixed` (the first fixed version), `summary` (one sentence, at most 1000 characters), `url` (https), `date` (`YYYY-MM-DD`). An advisory is never removed: a fixed one stays, its range says who is affected. `release-data.test.ts` (gateway structural tests) holds both files to the feed's guard. [`app/versions.json/route.ts`](../../apps/website/src/app/versions.json/route.ts) serves them as the feed: `force-static`, rendered once at build (`generated_at` is the build time), `Cache-Control: public, max-age=3600`; `buildVersionsFeed()` (`content/versions-feed.ts`) throws on a file `isVersionsFeed` refuses, so a malformed advisory fails the build. A changed advisory reaches the feed with the next deploy of the site, not before.

## Traps

- **A sample on the fallback fails the build**: `loadPlugins()` throws `ExampleError` (from `generate`, `type-check` and the unit tests alike) naming the plugin, the tool and the sample (`'<tool>' sample #n slice #m`), when a sample's slice matches no catalog entry or only the fallback (a missing entry), when `classify` refuses a sample not marked `expectDenied`, or accepts one that is. Fix the catalog or the sample in the plugin, as the plugin's coverage test would ask; never filter it out in the site.
- **Generated and gitignored** — never edit by hand: `.generated/`, `.source/`, `public/`, `content/docs/configuration/keys.mdx`, `content/docs/known-limitations.mdx`. The generator empties `public/` and removes every file marked `generated: true` on each run. `public/` holds `llms.txt`, `sitemap.xml`, `robots.txt` and the connect guides' screenshots (`BuiltSite.assets`: `plugins/<id>/connect/<file>`, copied from the plugin's `docs/connect/`; the internal-link test knows them) only: the Markdown twins, `plugins.json`, `llms-full.txt` and `versions.json` are routes (`LIVE_FILES`, `BUILT_ROUTE_FILES` in `outputs.ts`, which the internal-link test reads).
- **`revalidate` must be a literal** in a page or route file: Next.js reads it statically, so `export const revalidate = HEALTH_REVALIDATE_SECONDS` silently gives no caching. Write `3600` and let `live.test.ts` catch a drift.
- **`/.well-known/microsoft-identity-association.json` is a route, not a public file** (`app/.well-known/…/route.ts`, `force-dynamic`): the generator empties `public/`, and the ids must be read at request time so a change of the variable needs no build. No application id is written in the code.
- **`/twins/…` is reachable directly** (the proxy rewrites to it); it is not listed anywhere and serves the same text as the `.md` address.
- **`components/plugin/` imports relatively, never through `@/`**: the root `vitest.config.ts` maps `@/` to the gateway's `src`, and `plugin-page.test.tsx` renders `PluginPageView` with `react-dom/server`. Only the route file (`app/plugins/[id]/page.tsx`) uses `@/`.
- **The twin does not link to itself**: `pluginLinks()` ends with the `.md` address for the HTML page; the twin names `/plugins/<id>` instead (the internal-link test of `site.test.ts` knows pages, not twins).
- **Hand-written docs are plain Markdown in `.mdx`**: `loadHandwrittenDocs()` refuses an `import`/`export` line, a `<Tag` or a `{` outside code (write `your-domain` in prose, `<your domain>` in a code span).
- **Plugin strings go through `text()`**, which escapes Markdown. The plugins' README "Credential" sections are no longer read: the connect guide is section 7 of `/plugins/<id>` (`#connect`), from the declaration alone.
- **`/docs/providers/<id>` is a redirect, not a page** (`src/site/redirects.ts`, read by `next.config.ts`; the `.md` address goes to the plugin page's twin). The index `/docs/providers` stays a hand-written page. A link to a service's guide is `connectGuidePath(id)`.
- **A screenshot's words are derived, never written**: the provenance line is `screenshotAttribution` of the SDK, the same the gateway prints; the licence words travel in `ConnectFigureInfo.licenceWords` so that the page code imports nothing of the SDK at run time (the SDK is a devDependency, not transpiled). The credits line at the foot of `/plugins` lists each documentation and licence once, nothing when no page shows one.
- **Without `COLLECTOR_HOST`** every host is the site's and the collector routes refuse by themselves; with it, that host answers only `/v1/…` and a `Disallow: /` robots file.
- **No theme toggle on purpose**: it would need script and storage; dark follows `prefers-color-scheme`.

## Outside the repo — Vercel project

- Root `apps/website`, Node 22, framework Next.js, build `npm run build`, and **"Include files outside the root directory in the Build Step" on**: the generator reads `plugins/`, `docs/`, `deploy/` and workspace packages.
- Request-time variables: `COLLECTOR_HOST`, `COLLECTOR_SUPABASE_URL`, `COLLECTOR_SUPABASE_PUBLISHABLE_KEY`, and `MICROSOFT_IDENTITY_APP_IDS` (comma-separated Entra application ids; `/.well-known/microsoft-identity-association.json` answers Microsoft's publisher-domain check from it, 404 without it: the OAuth broker's `microsoft` client names vaubaan.com as its publisher domain, [oauth-broker-contract](oauth-broker-contract.md)); the build needs none. No log drain, no Observability Plus, no analytics.
- The pages under `/plugins` and the twins route run as functions once an hour (ISR); nothing to configure, Vercel's defaults carry it.

## Debug

- **`site.json is missing`** → `npm run generate --workspace @vaubaan/website`.
- **"not plain Markdown"** → a `<`, `{` or component in prose: use a code span.
- **MDX error in a generated page** → `escapeMdx()` missed a construct: add it to `markdown.ts` and `units.test.ts`.
- **Every plugin reads "not read"** → the collector did not answer within 4 s when the page was last rendered (`https://telemetry.vaubaan.com/v1/plugin_stats?tool=is.null`, `…/v1/plugin_instances`); the next render, within the hour, tries again. `/plugins/health` names the time of the last successful read.
- **Gateways "not read", calls fine** → `plugin_instances` is missing on the collector's store: apply `deploy/collector/schema.sql`.
- **A new release's minor reads "no call yet"** while the previous one had hundreds → expected: the list's second row keeps the previous minor; the plugin page lists the last ten versions.
