# Integration test plan

## Scope

- Vitest, headless, one process: the real composition root on a `:memory:` store with every plugin of the repository compiled in, a simulated IdP and mocked services. No browser, no database server, no real service (spec [vaubaan-gateway](../spec/vaubaan-gateway-10-tests.md#10-tests) §10 "Out of scope").
- Unit, integration and structural suites all run here (`npm run test`, part of `npm run ci`); what spec §10 requires is found by the `describe`/`it` titles, not by a map in this file.
- Browser journeys, the container and the manual acceptance run are in [e2e-tests.md](./e2e-tests.md). UI rendering is static markup only here; looks are judged on `/design`.

## Stack

- Discovery is `vitest.config.ts` `INCLUDE`: `apps|packages/*/tests/{unit,integration}/`, `plugins/*/tests/unit/`, `*.test.ts` beside the source in `apps|packages/*/src/`, `scripts/*.test.mjs`. Excluded: `apps/*/tests/e2e/` (Playwright) and `apps/gateway/tests/manual/` (scripts run by hand).
- Two Vitest projects. `shared`: every file but the isolated ones, run `--no-isolate` (one module graph per `forks` worker: re-evaluating the root for each file was more than half the run). `isolated`: `ISOLATED_TESTS` (`apps/*/tests/unit/app/**`), each file on a fresh graph. A plain `npx vitest run <path>` isolates every file.
- A test instance is `buildTestRoot` / `testRootDeps` (`apps/gateway/tests/integration/missions/support.ts`); every dependency it fakes goes through `RootDeps`, never a module mock. Each subsystem folder adds its own `support.ts`.
- Plugins: production compiles only `vaubaan` and `ssh` (`SHIPPED_PLUGINS`) and installs the others from the catalog; `memoryStoreDeps` compiles in `REPOSITORY_PLUGINS` (`tests/support/plugins/repository.ts`). A test meaning "every plugin we write" reads that list, never `SHIPPED_PLUGINS`.
- The catalog is a faked `fetch` serving real archives: `tests/fixtures/sigstore/` holds notion 0.2.0 as the catalog's release workflow signed it, verified offline; a company key is generated by the test (`generateSigningKey`).
- Fake upstreams: `mockFetch` (`@vaubaan/plugin-sdk/testing`, endpoints from the plugin's own credential spec), `FakeIdp` and `FakeGithub` (`tests/integration/auth/`), `FakeGithubHost` (a real bare repository behind `git http-backend`, driven by the real `git` client), `fake-imap.ts` (Gmail: IMAP, and `fakeSmtp` for its sends), `fake-caldav.ts`, `FakeOAuthBroker` (a real HTTPS server on loopback, the test-only `fake-enclave` platform the configuration can never name), `fakePushTransport` (`tests/support/notifications/`, through `RootDeps.notificationTransport`: what would leave for a push service, decrypted, and the answer the test picks), `fakeMessagingFetch`, `fakeResolver` and `fakeNoticeMailer` beside it (through `RootDeps.notificationFetch`, `notificationResolve`, `notificationMailer`: the body each messaging address would receive, the addresses a name resolves to, the mails; no network, no DNS). Notification delivery runs in the background: a test awaits `root.notifications.idle()` before it reads what was sent.
- Property tests use fast-check through `propertyRuns()` (`@vaubaan/plugin-sdk/testing`): seeded by `PROPERTY_SEED`, deterministic in CI; a failure prints its seed, replay with `FC_SEED=<seed> FC_RUNS=<n> npx vitest run <file>`.

## Conventions

- Test fakes and fixtures shared across suites live under `apps/gateway/tests/support/<subsystem>/` (`testing.ts`, the fake OAuth broker and its certificate), never under `src/`: no production file imports them.
- Naming: `*.test.ts(x)`; `*.property.test.ts` for property tests; `*.bench.test.ts` measures a cost rather than asserting a behaviour.
- Unit tests of a plugin live in `plugins/<id>/tests/unit/`; gateway integration tests in `apps/gateway/tests/integration/<subsystem>/`; tests that read the repository's own files (docs, Dockerfiles, catalogs, source) in `apps/gateway/tests/unit/structural/`.
- No module state survives a file: each test builds its own root on its own `:memory:` store, so the `shared` project's order never matters.
- A file that replaces a module (`vi.mock`) lives under `ISOLATED_TESTS`, otherwise the mock applies or not by the order files ran in; `structural/module-mocks-isolated.test.ts` refuses a `vi.mock` anywhere else (invariant `module-mocks-isolated` of `manifest.ts`).
- No test reaches a service or the network; any fetch the fake does not know rejects. Sockets are opened on loopback only: `plugins/ssh/tests/unit/host-key-pinning.test.ts` (an in-process ssh server), the fake broker, and `apps/oauth-broker/tests/` (its two listeners, a fake OAuth provider, a fake Confidential Space TEE server on a Unix socket in a temporary directory).
- Every plugin directory carries an identifier suite running hostile literals through classifier and executor (`assertIdentifiersRefused` of the testing kit), enforced structurally.
- Demo mode stays out of the application: its IdP, fake services and seed live in `apps/gateway/tests/demo/` only; `demo-safety.test.ts` checks that no route, no file under `src/` and nothing in the standalone build names `/__demo`, and that `assertDemoAllowed` refuses a production configuration. Tests of `tests/integration/demo/` that spawn the demo need a build.
- Structural invariants are indexed in `apps/gateway/tests/unit/structural/manifest.ts` (id, statement, source, proofs: file + test titles). `index.test.ts` fails when an invariant has no proof, a proof file or title is gone or would not run (`it.skip`, a comment), a test file of the folder belongs to no invariant, a spec §10 "Structural" bullet has no invariant or the reverse, or [threat-model](../handbook/threat-model.md) cites a missing invariant or file. A new structural test is added to the manifest in the same change.
- Coverage is measured, never gated: the weekly run's job `coverage` (`npx vitest run --coverage`, every source file counted, an unloaded one at 0 %) writes the lines covered per area and the 20 slowest test files to its summary (`scripts/test-report.mjs`), and keeps the HTML report a week. A number is a lead for the next test, not a target.
- A heavy file that times out on a loaded machine gets a timeout of its own in the file, with the measured duration in the commit; the slow list of the weekly report is where to look first.
- Tests that read docs parse exact shapes: the configuration keys table, the refusal table of the `vaubaan` plugin's handbook, spec §10 bullets, threat-model `[inv: id]` markers, the base-image refresh procedure. Restructure those docs with their tests running.

## Known gaps

- ⚠️ **Miro, Google Calendar, CalDAV, Gmail against real accounts** (spec [§5](../spec/vaubaan-gateway-05-composition.md#5-composition)) — fakes and captured or modelled tool lists only (Google Calendar: a mock of the REST API v3); Miro's `board_create` ran live once (its answer is the fixture), "create a board then draw on it" through a mission is still to run live.
- ⚠️ **Telemetry classes of the shipped plugins** (spec [§9](../spec/vaubaan-gateway-09-community-telemetry.md#9-community-telemetry)) — the reduction is tested on a fixture, not on each plugin's failures.
- ⚠️ **The collector's SQL against PostgREST** (spec [§9](../spec/vaubaan-gateway-09-community-telemetry.md#9-community-telemetry)) — `schema.sql` is checked as text and was applied by hand once; the `PT429` → 429 mapping comes from documentation.
- ⚠️ **Group shares through the `vaubaan` plugin** (spec [§4.1 bis](../spec/vaubaan-gateway-04-surfaces.md#41-bis-management-surface-the-vaubaan-plugin)) — tested in `AuthorityService`, not again over MCP.
- ⚠️ **A ref the account never discovered** (spec [§3.1](../spec/vaubaan-gateway-03-authority.md#31-the-chain)) — rejected with the classifier's sentence rather than `resource-not-in-mission`; only the rejection is tested.
- ⚠️ **A user removed from the IdP** (spec [§6](../spec/vaubaan-gateway-06-security.md#6-security)) — no deprovisioning feed; only an operator's deactivation sets `removed`.
- ⚠️ **Entra ID above the group limit** (spec [§4.2](../spec/vaubaan-gateway-04-surfaces.md#42-human-surface)) — overage markers replayed by `FakeIdp`, never against Entra.
- ⚠️ **The door's authority re-check cost** (spec [§4.1](../spec/vaubaan-gateway-04-surfaces.md#41-execution-surface)) — measured by `door-latency.bench.test.ts`, not asserted.
- ⚠️ **The OAuth broker in a real enclave** ([oauth-broker](../spec/oauth-broker.md) §4) — the Confidential Space adapters (broker and gateway) run against fakes and self-signed tokens; no real attestation token or Secret Manager unseal has been run.
- ⚠️ **`ssh__exec` against a real host** (spec [§5](../spec/vaubaan-gateway-05-composition.md#5-composition)) — by design: a fake transport and the loopback server only.
- ⚠️ **Web push against a real push service** (spec [§4.2 bis](../spec/vaubaan-gateway-04-surfaces.md#42-bis-notifications)) — no test reaches FCM, Mozilla, Apple or WNS; the encryption is pinned to the RFC 8291 Appendix A vector and the VAPID token verified with its public key, the delivery to a phone is checked by hand.
- ⚠️ **Messaging addresses against the real services** (spec [§4.2 bis](../spec/vaubaan-gateway-04-surfaces.md#42-bis-notifications)) — the Slack, Teams, Discord and ntfy bodies are pinned to their documented formats, never posted to the services; the pinned socket of the free hosts (`messaging/posters.ts`) is tested refusing a name that resolves inside the network, never reaching a public server.
- ⚠️ **Each dispatch point of a notification over the root** (spec [§4.2 bis](../spec/vaubaan-gateway-04-surfaces.md#42-bis-notifications)) — a request opened and a mission orphaned are driven through the real root; an account expired, a permission request, a revocation by someone else, a failed backup and a recovery are covered by the dispatcher's test with faked reads, and their call sites by type only.
- ⚠️ **A plugin installed from the live catalog** (spec [§7.11](../spec/vaubaan-gateway-07-workflows.md#711-update-a-plugin)) — the versions feed and the archives are served by a faked `fetch`; the signature check runs offline on one captured release, never against the published catalog.
- ⚠️ **Two additions racing for the last place under a ceiling** (spec [§4.3 bis](../spec/vaubaan-gateway-04-surfaces.md#43-bis-ceilings-and-counters)) — the check reads the count before the write; the race is accepted (handbook [limits-and-counters](../handbook/limits-and-counters.md)) and not tested.
