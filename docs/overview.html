Security Gateway for AI Agents

Your AI agent, safely wired in.

Vaubaan sits between your AI coding tools and your cloud accounts — so your real credentials never leave your hands.

🏨 Think of it like a hotel key card system

Imagine you run a hotel. You wouldn't hand a guest your master key — they'd have access to everything, forever. Instead, you give them a key card that only opens their room, only while they're booked in.

AI coding agents face the same problem. To do useful work — push code to GitHub, trigger a deployment, read a database — they need credentials. But handing them your real API keys is like giving away your master key.

Vaubaan is the hotel key card system for AI agents:

  • You connect your real accounts to Vaubaan once, in a secure vault.
  • Each agent gets its own token (vbn_live_…) with a defined set of permissions.
  • The token only opens the doors you said it could.
  • Every use is logged. Revoke it anytime.
  • The agent never sees your real credentials.
How it works

Five steps, every request

When an AI agent needs to do something — create a branch, deploy a build, run a query — here is exactly what happens behind the scenes.

1

Agent makes a call

The AI agent sends a request through Vaubaan's MCP interface, including its vbn_live_… token. This is just like a regular API call — from the agent's perspective, it's talking to a tool.

2

Vaubaan verifies the token

Vaubaan checks: is this token real? Is it still active? What organisation, project, and roles does it belong to? All of this happens in milliseconds.

3

Policy engine decides

Vaubaan checks the agent's assigned roles against the requested action. "Can this token push to this specific repository?" If no, the request is rejected cleanly right here.

4

Vaubaan forwards with a fresh credential

If the policy says yes, Vaubaan mints a short-lived, single-use credential from your stored secrets, and makes the actual API call to GitHub, Vercel, Supabase, or whichever service was requested. The agent never sees this credential.

5

Result returned, audit log written

The result comes back to the agent. Simultaneously, Vaubaan writes a detailed audit log entry: who, what, when, which resource, and whether it was allowed or denied.

Key concepts

The building blocks

Vaubaan uses a handful of simple ideas that combine to give you fine-grained control. Here's what each one means.

🏢

Organization

Your team or company's top-level account in Vaubaan. All providers, projects, and tokens belong to an organization. Think of it as your company's entry in the Vaubaan directory.

🔌

Provider

A cloud service that Vaubaan knows how to talk to — GitHub, Vercel, Supabase, Railway, or an SSH server. You connect each provider once by giving Vaubaan your real credentials for it.

📁

Project

A sub-unit of your organization, usually matching one product or codebase. Each project gets its own set of resource bindings, roles, and access tokens — keeping things neatly separated.

📎

Provider Binding

Links a project to a specific resource within a provider — for example, the GitHub repository acme/website. Bindings scope what an agent can reach; without a binding, an action is automatically denied.

📜

Role

A named bundle of permissions. For example, github:developer might allow pushing branches and opening pull requests, but not deleting repositories. Roles are assigned to access tokens.

🔑

Access Token

A vbn_live_… key you give to an AI agent. It identifies which project and roles that agent has. The agent presents this token on every request — it is the agent's identity inside Vaubaan.

⚙️

Management Key

A vbn_mgmt_… key used by your own automation — CI pipelines, scripts — to mint short-lived agent tokens programmatically. Not for giving to agents directly.

Get started

Setting it up (as an operator)

You are the operator — the person who owns the cloud accounts and decides what agents are allowed to do. Setup takes a few minutes and you only do it once.

  1. Create your Vaubaan organization. Sign up at vaubaan.com and create an organization for your team or project.
  2. Connect a provider. Go to Providers and add your GitHub, Vercel, Supabase, or other credentials. Vaubaan stores them encrypted — this is the only time your real keys are entered.
  3. Create a project and bind a resource. Create a project (e.g. "Website"), then add a provider binding to tie it to a specific resource, like the acme/website GitHub repository.
  4. Define a role (or use a built-in one). Pick the right level of access — read-only, developer (push/PR), or admin. Roles are reusable across tokens.
  5. Mint an access token for your agent. Create a vbn_live_… token and assign it the project and role. Hand this token — and only this token — to your AI agent.
  6. Point the agent at Vaubaan's MCP endpoint. Configure the agent to use https://vaubaan.com/mcp with your token. The agent can now do its job, safely, within the boundaries you set.
